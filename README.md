# CellPeek

CellPeek 是一个面向飞书 / Lark 电子表格的 Chrome MV3 扩展。它把当前单元格的内容放到侧栏中，以更适合阅读、搜索、复制和编辑的方式展示，同时保留单元格与来源工作表之间的可靠关联。

CellPeek 的核心目标是：让用户在不改变表格视角的情况下阅读长文本、切换多个单元格对比，并安全地把修改写回原逻辑单元格。

## 功能概览

### 单元格展示

- 点击表格单元格后，在浏览器右侧打开或更新 CellPeek 侧栏。
- 支持单栏、左右分栏、上下分栏三种布局；分栏之间可以拖动调整比例。
- 每个分栏独立维护当前内容、展示格式、搜索状态、锁定状态和键入草稿。
- 地址和字数固定显示在分栏顶部，正文在独立滚动区域内阅读。
- 支持鼠标悬停提示、键盘焦点提示、紧凑响应式布局以及窄侧栏场景。
- 普通单击当前用户可查看的受保护文本单元格时，会从公式栏的完整只读值中尝试建立预览，不要求先打开飞书原生单元格详情。
- 捕获到明确只读证据时禁用键入；无法判断访问能力时保持现有写回验证行为。

### 展示格式

每个分栏都有自己的格式菜单：

- `自动`：有效 JSON 使用 JSON 结构视图，其余内容使用 Markdown 展示。
- `MD`：按 Markdown 规则解析标题、段落、列表、分隔线、链接、表格和数学公式。
- `JSON`：使用可折叠的 JSON 结构视图展示对象、数组和标量值。
- `原文`：保留原始文本与原始 Markdown / JSON 标记，不做格式转换。

自动模式不会因为普通文本“看起来像原文”就擅自切换到原文；只有用户明确选择 `原文` 时，才展示未解析的源文本。

### Markdown 与数学公式

- 修正多级标题、无序列表和有序列表的解析表现，避免标题标记遗漏或列表全部变成 `1.`。
- 支持 `---` / `***` / `___` 分隔线。
- 列表采用紧凑行距，标题层级有轻微但清晰的字号差异。
- Markdown 表格使用圆角容器包裹，支持横向滚动、单元格换行、自适应列宽和悬停反馈。
- 支持 LaTeX 行内公式和块级公式排版；公式只负责展示，不执行飞书表格公式。
- 链接可点击并在新标签页打开。

### JSON 结构视图

JSON 模式不是简单地把 JSON 当作一段原文，而是按语义层级呈现：

- 对象、数组可以展开和折叠；根节点默认展开。
- 小型 JSON 默认展开前两层，大型 JSON 自动收敛到更浅层级，用户可逐节点展开。
- 键、字符串、数字、布尔值、`null`、数组索引和标点使用不同的低饱和度颜色。
- 字符串中的换行会以可读的实际换行显示，长值会自适应容器宽度。
- 完整承载另一个有效对象或数组的字符串会以“JSON 字符串”标记递归展示；源 JSON 中它仍然保持字符串类型。
- JSON 深度超过 64 层或节点超过 10,000 个时，展示会出现安全截断提示，不修改源数据。

#### JSON 成员复制

结构视图中每个对象属性和数组项都可以单独复制，复制按钮在行悬停或键盘聚焦时出现：

- 对象属性复制为完整 JSON 片段，例如 `"name": "CellPeek"`。
- 数组项复制该项的 JSON 值。
- 内嵌 JSON 字符串的外层成员复制原始字符串表示；展开后的内层成员复制解码后的 JSON 片段。

### 分栏内查询

- 点击地址右侧的放大镜打开分栏内查询框；再次点击或按 `Esc` 收起。
- 搜索范围是当前分栏的当前展示表示，而不是始终搜索原始文本。
  - Markdown 模式搜索渲染后的内容，不把 `###` 等语法标记当作内容。
  - 原文模式搜索原始标记。
  - JSON 模式搜索当前结构视图中的键和值。
- 输入关键词后自动高亮匹配内容，并滚动到第一处匹配。
- 多处匹配显示 `当前序号/总数`，右侧箭头可以切换上一处和下一处。
- JSON 搜索会自动展开命中路径；关闭查询后恢复搜索前的折叠状态。
- 分栏激活时支持 `Ctrl+F` / `Cmd+F` 进入查询，不会修改飞书表格数据。

### 锁定、键入与安全写回

#### 锁定分栏

- 锁定后，分栏继续展示原单元格，不跟随表格后续选择变化。
- 锁定不等于固定屏幕坐标；表格滚动、左右移动、上下移动或切换工作表后，仍会保存原逻辑单元格快照。
- 解锁后恢复浏览状态，并刷新为当前有效的展示单元格。

#### 键入模式

- 当前展示单元格具有明确地址时，可直接点击键入按钮进入编辑。
- 初次进入工作表时已经激活并成功展示的单元格，可以直接键入。
- 取消锁定后仍可直接键入当前展示单元格，不强制用户重新点击。
- 锁定分栏仍然可以键入；完成时会自动切回来源浏览器标签页、来源工作表，并恢复目标单元格视角。
- 用户在长文本中搜索并滚动到某处后点击键入，会尽量保留原来的阅读位置和编辑光标位置。
- 点击 `完成` 写回当前草稿；点击 `放弃草稿` 可主动退出编辑，确认弹窗只在确有未保存修改时出现。
- 退出键入不会意外解除分栏锁定，也不会强制聚焦其他单元格。

#### 原逻辑单元格追踪

键入开始时会冻结一份目标快照，包括来源浏览器标签页、来源工作表、单元格地址、原始内容和邻近单元格特征。完成写回时：

1. 返回来源浏览器标签页和来源工作表。
2. 通过地址、公式栏内容、选区状态和稳定读取结果重新定位目标。
3. 如果行列插入、删除或移动导致地址变化，会在附近候选中使用原内容和邻近特征追踪原逻辑单元格。
4. 只在目标确认、来源页面确认和写回结果验证均通过后才提交。
5. 无法确认时不会静默写入其他单元格，而是保留草稿并进入“等待重新定位”。

等待重新定位时，用户可以连续点击不同单元格选择候选目标；提示中的地址会随最后一次有效点击更新，确认前不会写回。无效点击不会改变候选，也不会打断流程。

#### 写回策略

- 普通文本优先使用已验证选区的原生剪贴板粘贴链路。
- 清空内容使用删除事件。
- 写回后通过公式栏和选区稳定读取结果进行验证。
- 不直接修改公式栏 DOM，也不依赖滚动后的旧屏幕坐标。
- JSON 模式键入时，会先生成两空格缩进的格式化草稿；键和值的类型保持不变。
- JSON 草稿实时校验并显示错误行列；JSON 无效时 `完成` 按钮不可用，只有合法 JSON 才允许写回。

### 复制与调试

- 顶部复制按钮复制当前分栏的展示内容。
- JSON 结构视图支持成员级复制，复制结果是可独立解析的 JSON 片段。
- 调试栏默认收起，不会因为一次普通写回失败自动展开。
- 调试栏记录捕获、目标解析、粘贴、清空和验证阶段，可复制完整诊断报告。
- 诊断报告会区分 `目标未找到`、`目标失配`、`写回冲突`、`写回未验证` 等阶段，便于定位 Canvas / 虚拟化表格中的问题。

## 安装

建议使用当前稳定版 Chrome，并确保浏览器支持 Manifest V3 Side Panel API。

1. 下载或克隆本仓库。
2. 打开 `chrome://extensions/`。
3. 开启右上角的“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择本项目根目录。
6. 打开飞书 / Lark 电子表格，刷新页面。
7. 点击浏览器工具栏中的 CellPeek 图标打开侧栏。

更新本地代码后，在 `chrome://extensions/` 点击 CellPeek 卡片上的刷新按钮，再刷新飞书表格页面。

## 使用流程

### 查看一个单元格

1. 打开支持的飞书 / Lark 表格。
2. 点击目标单元格。
3. CellPeek 自动读取公式栏中的单元格内容并展示。
4. 使用格式菜单选择 `自动`、`MD`、`JSON` 或 `原文`。

### 对比两个单元格

1. 先选择 `左右分栏` 或 `上下分栏`。
2. 在分栏 1 中点击第一个单元格。
3. 激活分栏 2，再点击第二个单元格。
4. 分别使用锁定、搜索、复制或键入按钮。

### 编辑并写回

1. 确认分栏正在展示想要修改的单元格。
2. 点击铅笔图标进入键入模式。
3. 修改文本或 JSON 格式化草稿。
4. 点击 `完成`。
5. CellPeek 会回到来源位置并验证写回；成功后继续保留分栏内容和锁定状态。

如果目标发生结构变化，侧栏会保留草稿并提示重新定位。此时在来源工作表中点击目标单元格，确认候选地址后再完成写回。

## 支持的网站

插件只在以下站点注入内容脚本：

- `feishu.cn`
- `*.feishu.cn`
- `larksuite.com`
- `*.larksuite.com`
- `*.larkoffice.com`

不同租户、地区或客户端版本的表格界面可能存在 DOM、Canvas 和公式栏结构差异。CellPeek 会尽量通过稳定的地址和公式栏证据工作；无法确认时优先保护数据安全，不执行猜测写回。

## 权限与隐私

扩展使用的权限来自功能本身：

- `activeTab`、`tabs`、`windows`：切回来源浏览器标签页、恢复窗口焦点并处理跨标签页写回。
- `scripting`：在支持的表格标签页中执行受限的定位和写回辅助逻辑。
- `sidePanel`：显示 CellPeek 侧栏。
- `clipboardRead`、`clipboardWrite`：复制展示内容和准备安全的粘贴写回。
- 飞书 / Lark host permissions：仅在声明的表格域名上运行内容脚本。

CellPeek 不包含后端服务，不会把单元格内容上传到第三方服务器。内容处理、Markdown / JSON 渲染、搜索和写回验证均在浏览器本地完成。

## 项目结构

```text
.
├─ background.js                  # Service worker：打开侧栏、切换标签页、跨标签页消息路由
├─ content.js                    # 表格页面捕获、逻辑单元格定位、粘贴写回和结果验证
├─ sidepanel.html                # 侧栏结构与无障碍标记
├─ sidepanel.css                 # 布局、响应式 UI、Markdown / JSON / 编辑器样式
├─ sidepanel.js                  # 分栏状态、展示格式、搜索、键入、JSON 结构视图
├─ manifest.json                 # Chrome MV3 清单、权限和支持域名
├─ icons/                        # CellPeek 图标资源
├─ vendor/                       # 本地 Markdown-it、KaTeX 及许可证文件
├─ docs/adr/                     # 关键设计决策记录
└─ CONTEXT.md                    # 领域术语、状态和交互约束
```

## 开发与检查

项目不依赖构建工具，加载解压目录即可开发。修改后建议执行：

```powershell
node --check sidepanel.js
node --check content.js
node --check background.js
Get-Content -Raw -Encoding UTF8 manifest.json | ConvertFrom-Json
git diff --check
```

浏览器验证建议覆盖以下场景：

- 单栏、左右分栏、上下分栏以及分栏比例拖动。
- 初始激活单元格直接键入、锁定后键入、解除锁定后键入。
- 左右 / 上下滚动后键入、切换工作表或浏览器标签页后键入。
- 插入或删除行列后的原逻辑单元格追踪与等待重新定位。
- 自动 / MD / JSON / 原文格式切换，尤其是 Markdown 表格、标题、列表、分隔线和公式。
- JSON 折叠、嵌套 JSON 字符串、成员复制、JSON 搜索展开恢复和格式化键入。
- 长文本搜索、高亮、`1/5` 计数、上下匹配导航以及 `Ctrl+F`。

## 设计与安全决策

写回链路的关键约束记录在 [docs/adr/0001-write-back-to-logical-cell.md](docs/adr/0001-write-back-to-logical-cell.md)：

- 原逻辑单元格优先于原始屏幕坐标。
- 地址、来源工作表、公式栏内容和选区稳定性是主要证据。
- Canvas 上的活动单元格 DOM 和屏幕坐标只能作为辅助证据。
- 目标或结果无法验证时保留草稿，不静默覆盖其他单元格。

这些约束也是 CellPeek 在滚动、虚拟化渲染、跨工作表和跨标签页场景下的安全边界。
